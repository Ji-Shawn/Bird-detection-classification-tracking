# 技能包(zynq-pl-accel)提炼过程总结

> 本技能包不是事先设计的规范,而是**事故驱动的事故日志 → 可复用规则**的提炼产物。
> 每条规则都满足三个条件:① 来自一次代价明确的失败或观察(多数对应数小时弯路);
> ② 有针对该规则的验证实验(复现-修复-回归);③ 标注了适用边界(何时成立、何时失效)。

## 1. 提炼方法论

```
失败/异常现象 → 最小可复现实验 → 根因分离(排除法/对照法)→ 规则化(含边界)
→ 固化进 SKILL.md → 后续同类事故用该规则秒级定位(有效性回验)
```

三条铁律贯穿始终:
- **对黄金向量对拍是铁律**:任何"看起来合理"都不算数,只认逐字节零差异;
- **先小步验证再推进**:每条规则验证用单层(L01/L02)或单层对照(L21)实验,不直接上全量;
- **版本化资产**:bit/ELF/源都有备份锚点,任何实验可回退到已知好状态。

## 2. 按主题的来源-验证-边界对照

### 2.1 数据通路类(M1 数据通路排障沉淀)

| 规则 | 来源(失败/观察) | 验证方式 | 边界 |
|---|---|---|---|
| BD 单针桩网:GUI 手动断线会生成静默 stub net,信号被绑常量 | M1:引擎假死,BD 界面一切正常,只有生成 `system.v` 里 `xxx(1'b0)` 可见 | 在集成脚本里固化"单针桩网清理循环 + HDL 绑死自检"两道保险,后续多次改线均当场捕获 | 只对 BD 手工改线场景;批处理脚本自动连线无此风险 |

| 启动顺序铁律(停 A9→fpga→ps7_init→post_config) | M1:PL 复位瞬间 PS 访问 PL,总线挂死毒化 DAP | 形成固定驱动脚本顺序后,数百次下载未再发生 | JTAG 流程;SD/QSPI 启动另有约束 |

### 2.4 调试基础设施类(长期血泪)

| 规则 | 来源 | 验证方式 | 边界 |
|---|---|---|---|
| DAP 卡死恢复链(fpga 重载→rst -system→重枚举→ps7_init) | 未决问题 2:DAP status 0xF0000021 反复,只有断电能清 | 形成恢复链后连续多次免断电救回;并固化了"rst -system 后必重跑 ps7_init(DDR held in reset 不是 wedge)"的区分判据 | 大多数 wedge;深度毒化(如写过 GT/PT 寄存器)仍需断电 POR |
| GT/PT 寄存器禁区(0xF8F00200/0xF8F00600) | 09-23 计时标定顺手写了私有定时器寄存器,之后所有运行产出确定性错误结果 | 断电 POR 恢复后,该禁区写入文档;改用主机时间戳/PMCCNTR 比值法标定 | 永久禁区,无任何例外 |
| cosim 是引擎 vs harness 的判官 | M5.4:引擎与 harness 互相甩锅,白查一天 | cosim 绿 → harness 侧问题(查出地址图重叠);cosim 挂 → 引擎侧 | 判官效力被后来证伪过一次:2026-09-26 发现"cosim 原理性照不到"的流时序类 bug(改以上板 ILA 为准) |
| DDR 数据腐烂(快速重跑前必疑数据) | "多瓦片 PW 第 2 帧挂"白查一轮,实为 wedge 事故期间个别字节被改写 | 全量重灌后旧 bit 62/62 全绿证伪;此后 LOAD=1 成铁律,快速重跑前抽查字节 | wedge 事故后必查;干净流程下可信任 |
| ILA 改变布局布线("加 ILA 病就好") | 阅读三篇 FPGA 实战文 + 自身证据(m54ila 是唯一稳定 bit) | 判案改用不带 ILA 的构建;ILA 结论只当线索不当证据 | 边际时序类问题;逻辑性问题不受影响 |
| 未约束路径检查 | 同上文警示"报告全绿可能只是没检查到" | 本工程实测:无未约束路径(report_unconstrained 表为空) | 每次换约束后必查 |
| 边际 hold 时序(WHS<0.05ns 数据会确定性出错) | perf 版构建确定性错数据(同位置复现),源级不可能错(L01 DW 未改) | 换 WHS 更健康的构建复验;判据入档 | WHS <0.05ns 的构建不可信;与逻辑无关,勿误改代码 |
| 跑完测试脚本收尾必停 A9 | 挂死后 A9 空转轮询 DMA,下次 fpga 重载必撞毒 DAP | 固化进 drive_net_fast.tcl 后,连续 wedge 显著减少 | JTAG 驱动场景 |

### 2.5 性能与集成类

| 规则 | 来源 | 验证方式 | 边界 |
|---|---|---|---|
| PMCCNTR 是 ÷64 分频(1 拍≈95.72ns) | M5.5 计时数据偏小 ~10 倍无法解释 | 用已知工作量(私有定时器/主机时间戳)标定 | 本板;标定前不许下性能结论 |
| AXI DMA 流口位宽是独立参数 | 64 位化时只改 M_AXI 宽,MM2S 流还是 32 位,引擎被静默补零,系统网表里 `{32{1'b0},...}` | 显式补 `c_m_axis_*_tdata_width` 后查 system.v 线宽 [63:0] 确认 | AXI DMA 全系列;只改 MM 宽永远不够 |
| 瘦流循环 ~17 拍/拍、胖循环 ~2.6 拍/拍 | M5.5 斜率探针四点拟合 + 逐层计时分解 | 引擎结构选型直接照此(读写算一体优先) | HLS 顺序循环的 FSM 税;手写 RTL 无此约束 |
| 手写 RTL 存储纪律:宽字整字访问、1R1W、多维数组不推断存储 | M6-RTL:2D 数组 1Mbit 超限、异步读大数组 mux 爆炸 704K LUT、2D 不推断 distributed RAM | 独立综合三个变体对照(2D 1037 LUT mux vs 1D RAMD64E),最终宽字版 LUT 22K 达标 | 大数组必须 BRAM(同步)或 1D LUTRAM(单异步读);FF 阵列只对 ≤几百项适用 |

## 3. 提炼过程的自我验证(规则如何证明"有效")

- **回归守门**:每条规则落地后必跑 62 项隔离回归(51 层+10 Add+L00)与链式 top1,全绿才算数;
- **对照实验习惯**:任何归因都要一个"只差一个变量"的对照(旧 bit vs 新 bit、B2' vs B3/B4 只差一条 pragma、带不带 ILA、100MHz vs 降频);
- **失效也记录**:被推翻的结论(如"流水即毒")原地保留并标注"已被 §5g 推翻"——技能的边界就是靠这些反例划出来的;
- **他人可复现**:所有规则配一键命令(恢复链、自检项、对拍脚本),换一个人/换一个 session 能原样执行。

## 4. 边界总原则

1. **仿真层级的边界**:csim 证功能、cosim(RTL)证引擎逻辑、上板证时序/接口交互——三层各有照不到的东西,结论必须注明验证层级;
2. **环境的边界**:板子健康度是变量(劣化期所有失败都需 POR 后复测才能归因);
3. **工具的边界**:HLS 的行为按版本(2023.2)记录,自动流水化等实现细节不保证跨版本成立;
4. **结构的边界**:每条性能/结构规则都带反例锚点(哪次实验推翻了它的泛化版),防止规则被过度套用。
