# 数值与数据通路排障：一次只验证一个假设

## 使用前提

需要输入数据、独立参考结果、实际执行入口和输出采集方式。数据至少说明 dtype、shape、排列顺序、字节序、量化参数和有效长度。缺参考生成器时，先把已有固定参考样本作为有限用例；不要凭空声称已完成全部算子的黄金验证，也不要引用未随包提供的抽层脚本作为必经步骤。

当前包的样本位于 `data/models/samples/`，模型资产清单位于 `data/models/assets_manifest.json`。固定样本能验证给定输入，不代表测试集准确率。参考来源和实际输出来源必须分别记录；把同一份 `expected` 复制为 `actual` 不能算验证。

## 排障步骤

| 步骤 | 具体操作 | 能排除的问题 | 何时停止下结论 |
| --- | --- | --- | --- |
| 1. 固定对象 | 记录源码/bit/ELF/模型哈希及工具版本，保存运行命令 | 运行了旧产物或不配套的固件 | 没有任何版本标识，或运行过程中输入被改写 |
| 2. 证明读到了数据 | 检查文件打开返回值、读取字节数、首尾样本和比较数量 | 空输入、路径错误、零比较、X 值伪通过 | 文件缺失、长度不符、RTL 输出含 X/Z、比较数量为零 |
| 3. 检查数据契约 | 核对 int8 符号、字节序、NHWC/NCHW、scale/zp、padding、尾块、饱和与舍入策略 | 布局、类型或量化语义差异 | 无法确定参考模型的舍入规则或数据布局 |
| 4. 检查传输契约 | 列出所有 DDR 区间，检查重叠与生命周期；核对 DMA 实例的实际参数、长度、TLAST、错误状态和超时 | 权重/结果覆盖、错长度、尾拍不一致、缓存可见性问题 | 活动地址未知、原始状态未保存，或参考与实际输入不相同 |
| 5. 缩小用例 | 单层 → 多瓦片 → 连续帧；同时加入随机反压、末块不整除和复位重启 | 只在状态延续、尾块或停顿时出现的错误 | 最小用例仍不确定；不要同时重构多个模块掩盖原因 |
| 6. 对比并定位 | 记录 mismatch 数、最大误差、首错索引及附近数值；按通道/行/块边界分析分布 | 有助于选择地址、排程、量化或计算假设 | 只有“看起来差不多”或只看 top1，缺所需数值证据 |
| 7. 验证一次修改 | 保留失败用例，改变一项因素，重跑原失败用例及必要边界用例 | 修正是否针对原问题，是否破坏邻近行为 | 只运行了新的容易通过的输入，或测试通过条件被同时放宽 |

## 不同症状的首个实验

- **只有后续帧错误**：记录每帧有效读写计数、idle/start 状态及缓冲区所有权，比较全新初始化和连续运行；不先假定 PIPELINE 是根因。
- **停顿后漏一个或多个字**：检查数据、valid、计数器、地址和计算管线在同一个时钟使能下的变化；以随机反压重现。不要只增加输出 FIFO 然后忽略内部状态。
- **错误严格跟随块/行/通道边界**：先核对末组装配、padding、布局和位宽，再查 MAC 算术。记录首错位置比只报总错误数更能区分假设。
- **新旧固件都错**：先核对输入与权重的实际内容、缓存可见性、地址重叠和重启状态。不能因文件未改变就断言 DDR 内容也未改变。
- **RTL 仿真全通过而板上不对**：确认测试平台读入了真实黄金数据、比较数量非零、初始化/反压/跨帧用例已覆盖；再检查约束与运行条件。仿真与硬件使用了什么不同条件应写清楚。

## 如何报告效果

使用 [validation_record.md](../assets/validation_record.md) 写明“原失败输入、原症状、假设、改动、复跑命令、实际结果、覆盖范围”。没有板卡复测时，结论限定为主机测试或仿真。时延需要计时方法、时钟或计时器标定、预热方式、样本次数和统计方法；一条未标定的计数器读数不足以证明性能。

该流程来自项目旧排障记录和本次交付审查发现。旧案例与现役规则的区分见 [casebook.md](casebook.md)；流程本身没有附带新的算子、板卡或准确率测量。
